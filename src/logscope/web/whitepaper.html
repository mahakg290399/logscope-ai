1. The problem we solve

Modern services emit thousands of log lines per second across multiple files, hosts and formats. Engineers face four pains:

  1. Volume without signal — repetitive lines bury the one new error that matters.
  2. Slow correlation — connecting a spike in service A to a timeout in service B is manual grep work.
  3. Alert fatigue — threshold alerts fire on noise; real incidents hide inside them.
  4. Unsafe AI shortcuts — pasting raw logs into an LLM leaks passwords, tokens, emails and customer IDs.

LogScope treats logs as an application heartbeat: compress repetition into templates, watch the pulse for arrhythmia with deterministic rules, and call the LLM only as a triage copilot over sanitized, bounded evidence.

2. Design principles

  • Sanitize first, stream second. Raw lines never cross the Kafka boundary and never enter an AI prompt. Redaction + client-ID hashing happen in the collector.
  • Deterministic detection before AI. New-template, frequency-spike (z-score ≥ 3.0) and error-burst rules fire on math; the model only judges whether it deserves investigation.
  • Bounded everything. Max 5 redacted samples per template per 5-minute bucket; bounded queues that drop oldest-first with visible counters instead of blocking.
  • Honest UI. Dropped events, consumer lag, AI failures and data-loss warnings are first-class dashboard citizens — the system never claims complete analysis when data was dropped.

5. Dashboard guide — every box on screen

Navbar: Live Stream + v2.0

Pulsing Live Stream pill reflects SSE connectivity (green = connected). The v2.0 badge marks the release; this whitepaper link sits beside it. The WAL SQLite • Sanitized Kafka note states the storage/streaming posture.

Warning banner

Appears only when something needs attention: backpressure drops, Kafka lag, or AI provider errors with retry state. Hidden when healthy — its absence is itself a signal.

KPI cards

  • Ingestion Rate — lines/sec across all tailers, plus lifetime total. Validates the ~1,000 LPS target.
  • Buffer Lag & Drops — queued observations and cumulative dropped count. Any non-zero drops mean triage is approximate.
  • Active Anomalies — triaged incidents in the current window.
  • Drain3 Clusters — unique templates mined; click to open the template browser, with active source count below.

5-Minute Ingestion Volume & Anomaly Timeline

Chart.js chart of bucketed observation volume (cyan) overlaid with error spikes (rose), fed by /api/buckets/timeline. Refresh icon reloads on demand; it answers “did anything just change?” at a glance.

Active Anomalies + filters

Each card carries an INC + 7-digit incident number, severity (Sev-0 critical … Sev-4 info), confidence (very-low…very-high), AI summary, evidence (template IDs, counts, source path/line), possible causes and recommended actions. The auto-refresh dropdown (5s/10s/30s/60s/Off) plus manual Refresh control polling; severity/application/environment/source filters narrow the feed. Empty state (“All Services Operating Normally”) confirms detectors ran and found nothing — distinct from a disconnected stream.

Dismissed Anomalies Archive

Collapsible history with outcome badges: green Resolved, amber False Alarm, slate Transient. Nothing is deleted — every verdict stays queryable for future AI context.

Ask SRE Copilot

Textarea that morphs into a persistent chat thread on first answer, with follow-up input. Queries embed against historical templates/incidents and answer with evidence references — or explicitly state when evidence is insufficient.

Monitored Sources

Each configured source with application, environment, path and heartbeat status. Read-Only guarantees the collector never writes to log directories.

Incident Action & Resolution modal

Three outcomes: Resolved (fix notes indexed into vector memory for future triage), False Alarm (expected/harmless, kept out of resolution memory), Transient (blip, quick dismiss).

Mined Templates + drill-down modal

Template browser; per-template drill-down shows the pattern, founding sample message, 5-minute bucket rollup history table and bounded sanitized evidence samples — the full audit trail from pulse to verdict.
